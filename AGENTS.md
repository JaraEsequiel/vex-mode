# vex-mode — instructions for agents maintaining this repo

## Mission

This repo is an Antigravity plugin: Vex's working mode for agents, built on pstack (Lauren Tan / poteto). It is maintained by agents. Every lesson ends in structure (a check, a hook, a test), not in more prose. The design is `docs/specs/2026-11-18-vex-mode-design.md`; read it before changing anything structural.

## Map

- `plugin.json`: plugin manifest. `name` must stay `vex-mode`.
- `harness/claude-code/`: the plugin for Claude Code, generated by `python3 scripts/build_plugin.py --harness claude-code` and committed; never edit it by hand. `.claude-plugin/marketplace.json` publishes it (`claude plugin marketplace add JaraEsequiel/vex-mode`, then `claude plugin install vex-mode@vex`).
- `rules/AGENTS.md`: always-on core loaded in Vex's sessions. Keep it minimal.
- `skills/vex-mode/`: the router (`SKILL.md`), `worker.md` (rules every subagent inherits), `playbooks/`.
- `skills/principle-*/`: one principle per skill.
- `skills/agent-ready/`: prepares another repo for agents; `templates/` holds the files it copies there (the Stop hook is tested in `scripts/tests/test_check_on_stop.py`).
- `agents/vex-agent.md`: the subagent definition.
- `adapters/claude-code.md`: maps the agy names in the skills to Claude Code (copied from pstack's `docs/harness/claude-code.md` and adapted). Evidence for its Claude Code facts: `docs/decisions/2026-11-19-claude-code-probes.md`.
- `hooks.json` + `hooks/`: mode hooks (activation, irreversible pause, stop gate) for agy and Claude Code; each tells the harness from the payload. `hooks/session_start.py` loads the always-on core in Claude Code, which has no plugin rules. The Claude Code `hooks.json` is written by the build.
- `checks/`: deterministic structural checks. `checks/run.py` runs all of them.
- `evals/`: `run.py` (the eval harness; a case runs on agy, or on Claude Code with `--harness claude-code` or `"harness": "claude-code"` in its `case.json`, using the models under its `"claude_code"` key), `harness/` (`judges.py` calls the judge over API; `quality.py` and `quality_judge.py` measure code quality on passing runs, design §8.2.1), `judge.json` (judge provider, model, effort), and per skill `evals/<skill>/cases/`, `results/` and `calibration/` (`run.py calibrate`: the base plugin against no plugin on Claude Code, to show a case measures the plugin at all). Never inside `skills/`: a candidate must not see them.
- `scripts/vendor.py`: copies pstack files verbatim and records provenance (including the upstream commit of each file).
- `scripts/upstream_drift.py`: compares every copied file with pstack upstream; a weekly workflow keeps one issue, "pstack upstream drift", in step. An adapted file that changed upstream is reconciled by re-applying the upstream diff, then `--accept`; never by re-copying it.
- `scripts/build_plugin.py`: exports only the plugin's parts; install with `--install`, never `agy plugin install` on the repo. `--harness claude-code` regenerates `harness/claude-code/`; run it after any change to `skills/`, `agents/`, `rules/`, `hooks/`, `adapters/` or `plugin.json`.
- `scripts/scheduled_correct.py`: the weekly unattended `/correct` run and its systemd timer (`install`, `run`, `uninstall`).
- `scripts/render_design.py`: renders `docs/specs/*-design.html` from the design's Markdown (template: `scripts/design_template.html`). Edit the `.md`, then run it.
- `vendor.lock`: provenance for every file under `skills/`, `rules/`, `agents/`, `adapters/`.
- `docs/specs/`, `docs/plans/`, `docs/decisions/`: design, plans, decision log.

## How to verify a change

```bash
python3 -m unittest discover -s checks/tests \
  && python3 -m unittest discover -s scripts/tests \
  && python3 -m unittest discover -s hooks/tests \
  && python3 -m unittest discover -s evals/tests \
  && python3 checks/run.py \
  && python3 scripts/validate_plugin.py
```

`scripts/validate_plugin.py` is `agy plugin validate --strict` with one documented exception: agy warns that this root `AGENTS.md` is never loaded by the plugin. That is intended; this file is for agents working in the repo, not for plugin users.

## How to bring in something that already exists

Never rewrite what pstack (or another source) already has.

1. `python3 scripts/vendor.py <upstream_root> <upstream_path> <dest>` for each file. Commit only that, as `vendor: copy <thing> from pstack@<sha>`.
2. In a separate commit `adapt: <thing> for antigravity`, make only the edits Antigravity needs: paths, model slugs, tool names, renames, removing references to skills not vendored yet. In `vendor.lock`, set `"adapted": true` on that file (unadapted files must stay byte-identical to upstream), list removed references in `removed_refs` (what to restore when that skill is vendored), and keep in `pending_refs` only references still in the text that point to skills not vendored yet. When a skill named in `removed_refs` gets vendored, restore the upstream text that names it in the same change. Anything we add that upstream does not have goes in `local_additions` with a pointer to its evidence, so a later reconciliation keeps it.

A new file that has no upstream goes under `original` in `vendor.lock`.

## How to change a skill

A skill change ships with evidence for its exact version (its tree hash):

1. Commit the change, then run `python3 evals/run.py <skill> <case>` (playbook: `skills/vex-mode/playbooks/eval.md`). It installs each arm's build and restores the user's plugin.
2. Read every candidate's output and transcript in the printed run dir, compare with the judge, then `python3 evals/run.py verdict <result> <promote|reject|inconclusive> "<synthesis>"`.
3. If no eval can measure the change, add a waiver result with a reason instead. The user accepts or rejects it in the PR.

A PR that changes `skills/<name>/` without a valid result for its current tree hash fails CI. A change to `hooks/`, `rules/`, `agents/`, `hooks.json` or `plugin.json` counts as a change to `vex-mode`.

If an eval was killed before it restored the user's plugin, the next eval refuses to start; run `python3 evals/run.py restore`.
